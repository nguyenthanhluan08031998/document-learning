Structured logging & ngữ cảnh

Log dạng câu văn chỉ con người đọc được. Log dạng JSON có trường rõ ràng thì máy lọc, đếm, vẽ biểu đồ được: “tìm mọi lỗi của đơn 42”, “thời gian xử lý trung bình của /orders”. Đây là chuẩn cho hệ thống backend hiện nay.

{
"level"
"msg"
"reqId"
}

01Structured logging

// Plain text: hard to search and parse
[2026-10-19 01:15:02] INFO Order 42 created by user 7 total 350000
{"level":30,"time":"2026-10-19T01:15:02.311Z",
 "service":"order-svc","reqId":"9f2c…",
 "msg":"order created",
 "orderId":"42","userId":"7","total":350000}
  • msg là câu cố định (“order created”), dữ liệu thay đổi đưa vào trường riêng. Nhờ vậy gom nhóm được theo msg.
  • Thống nhất tên trường trong toàn công ty: userId chứ không lúc user_id lúc uid.
  • Khi chạy local, dùng pino-pretty để in ra dạng dễ đọc; production giữ JSON.

02Dùng pino

import pino from "pino";

export const logger = pino({
  level: process.env.LOG_LEVEL ?? "info",
  base: { service: "order-svc", version: process.env.APP_VERSION },
  timestamp: pino.stdTimeFunctions.isoTime,
  redact: ["req.headers.authorization", "*.password", "*.cardNumber"],
  // Pretty output only on a developer machine
  transport: process.env.NODE_ENV === "development" ? { target: "pino-pretty" } : undefined,
});

logger.info({ orderId: "42", total: 350_000 }, "order created");
logger.warn({ attempt: 2, gateway: "vnpay" }, "payment retry");
logger.error({ err: new Error("timeout") }, "payment failed");

Thứ tự tham số của pino: object ngữ cảnh trước, message sau. Truyền lỗi qua khóa err để pino tự in stack trace và cause.

03Child logger & ngữ cảnh

// A child logger copies the parent config and adds fixed fields to every line
const orderLog = logger.child({ module: "checkout", orderId: "42" });

orderLog.info("reserving stock");      // includes module + orderId automatically
orderLog.info({ items: 3 }, "stock reserved");
orderLog.error({ err }, "charge failed");

Thay vì lặp orderId ở mọi dòng, tạo child logger một lần cho mỗi request, mỗi job hoặc mỗi message đang xử lý.

04Request ID xuyên suốt

Mỗi request nhận một ID duy nhất, gắn vào mọi dòng log trong lúc xử lý request đó, và chuyển tiếp sang service khác qua header. Tra một ID là thấy toàn bộ câu chuyện.

import { AsyncLocalStorage } from "node:async_hooks";
import { randomUUID } from "node:crypto";
import type { Logger } from "pino";

// Holds the per-request logger across every await, without passing it around
const als = new AsyncLocalStorage<Logger>();
export const log = () => als.getStore() ?? logger;

app.use((req, res, next) => {
  const reqId = req.header("x-request-id") ?? randomUUID();
  res.setHeader("x-request-id", reqId);
  const child = logger.child({ reqId, method: req.method, path: req.path });
  const start = performance.now();
  res.on("finish", () =>
    child.info({ status: res.statusCode, ms: Math.round(performance.now() - start) }, "request completed"));
  als.run(child, next);
});

// Anywhere deeper in the code: no logger parameter needed
export async function reserveStock(orderId: string) {
  log().info({ orderId }, "reserving stock");   // reqId is included automatically
}

// Forward the id to downstream services
await fetch(`${INVENTORY_URL}/reserve`, { headers: { "x-request-id": currentReqId() } });
Với Kafka, RabbitMQ, NATS: đặt request ID (hoặc traceparent) vào header của message, consumer đọc ra và tạo child logger tương ứng. Nhờ vậy một luồng đi qua cả API lẫn messaging vẫn nối được.

Các thư viện như pino-http làm sẵn phần middleware này.

05Che dữ liệu nhạy cảm

const logger = pino({
  redact: {
    paths: ["req.headers.authorization", "req.headers.cookie", "*.password", "card.number"],
    censor: "[REDACTED]",
  },
});

logger.info({ user: { email: "an@example.com", password: "123456" } }, "login");
// -> {"user":{"email":"an@example.com","password":"[REDACTED]"},"msg":"login"}

06Hiệu năng

  • console.log có thể ghi đồng bộ (ra file, terminal tùy hệ điều hành), không có level hay JSON, và chậm khi log nhiều; pino được thiết kế để ghi rất nhanh và đẩy phần định dạng nặng sang worker thread (transport).
  • Không ghép chuỗi tốn kém khi level đang tắt: if (logger.isLevelEnabled("debug")) logger.debug(buildBigReport()).
  • Không log trong vòng lặp nóng; log tổng kết sau vòng lặp.
  • Lượng log lớn thì lấy mẫu (sampling): giữ 100% lỗi, chỉ 1–10% log request thành công.
  • Khi tiến trình thoát, flush log còn trong bộ đệm để không mất những dòng cuối, thường là những dòng quan trọng nhất.
