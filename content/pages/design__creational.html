Creational: cách tạo đối tượng

Năm pattern giúp tách việc tạo đối tượng ra khỏi nơi dùng đối tượng, để code dùng chỉ biết interface chứ không biết lớp cụ thể.

PatternTên ViệtÝ tưởng một câu
SingletonMột thể hiện duy nhấtẨn constructor, cung cấp một điểm truy cập trả về cùng một thể hiện.
Factory MethodPhương thức tạoĐưa việc tạo đối tượng vào một phương thức; lớp con hoặc tham số quyết định tạo loại cụ thể nào.
Abstract FactoryNhà máy trừu tượngMột interface factory có nhiều phương thức tạo, mỗi hiện thực tạo ra một bộ đồng nhất.
BuilderXây từng bướcTạo đối tượng qua chuỗi lời gọi có tên rõ ràng, cuối cùng gọi build().
PrototypeNhân bảnSao chép một đối tượng mẫu rồi chỉnh phần khác biệt.

01Singleton Một thể hiện duy nhất

Vấn đềCần đúng một đối tượng dùng chung cho cả ứng dụng, ví dụ cấu hình hoặc connection pool, và không muốn mỗi nơi tự tạo một bản.
Ý tưởngẨn constructor, cung cấp một điểm truy cập trả về cùng một thể hiện.
class Config {
  private static instance: Config | undefined;
  private constructor(readonly dbUrl: string) {}

  static get(): Config {
    // Lazily create the single instance on first access
    if (!Config.instance) Config.instance = new Config(process.env.DB_URL ?? "");
    return Config.instance;
  }
}

const a = Config.get();
const b = Config.get();
console.log(a === b); // true
Khi nào dùngTài nguyên dùng chung thật sự duy nhất: logger, config, pool.
Lưu ýDễ thành biến toàn cục trá hình, khó test vì không thay được. Trong TypeScript, một module export sẵn một object (export const config = …) đã là singleton; ưu tiên dependency injection.

02Factory Method Phương thức tạo

Vấn đềCode tạo đối tượng bằng new rải khắp nơi, mỗi lần thêm loại mới phải sửa nhiều chỗ.
Ý tưởngĐưa việc tạo đối tượng vào một phương thức; lớp con hoặc tham số quyết định tạo loại cụ thể nào.
interface Notifier { send(to: string, msg: string): Promise<void>; }

class EmailNotifier implements Notifier {
  async send(to: string, msg: string) { /* call SMTP */ }
}
class SmsNotifier implements Notifier {
  async send(to: string, msg: string) { /* call SMS gateway */ }
}

type Channel = "email" | "sms";

function createNotifier(channel: Channel): Notifier {
  // The only place that knows concrete classes
  switch (channel) {
    case "email": return new EmailNotifier();
    case "sms": return new SmsNotifier();
  }
}

await createNotifier("sms").send("0901...", "Đơn hàng đã giao");
Khi nào dùngNơi dùng chỉ cần biết interface, loại cụ thể chọn theo cấu hình hay dữ liệu.
Lưu ýĐừng tạo factory cho lớp chỉ có một cách khởi tạo; thêm lớp trung gian vô ích.

03Abstract Factory Nhà máy trừu tượng

Vấn đềCần tạo cả một bộ đối tượng đi cùng nhau (ví dụ storage + queue của AWS, hoặc của GCP) và không được trộn lẫn hai bộ.
Ý tưởngMột interface factory có nhiều phương thức tạo, mỗi hiện thực tạo ra một bộ đồng nhất.
interface Storage { put(key: string, data: Buffer): Promise<void>; }
interface Queue { publish(msg: string): Promise<void>; }

interface CloudFactory {
  createStorage(): Storage;
  createQueue(): Queue;
}

class AwsFactory implements CloudFactory {
  createStorage(): Storage { return new S3Storage(); }
  createQueue(): Queue { return new SqsQueue(); }
}
class GcpFactory implements CloudFactory {
  createStorage(): Storage { return new GcsStorage(); }
  createQueue(): Queue { return new PubSubQueue(); }
}

// Application code depends only on the abstract factory
function bootstrap(cloud: CloudFactory) {
  const storage = cloud.createStorage();
  const queue = cloud.createQueue();
  return { storage, queue };
}
Khi nào dùngNhiều họ sản phẩm thay thế nhau trọn gói: theme giao diện, nhà cung cấp cloud, môi trường test và production.
Lưu ýThêm một loại sản phẩm mới phải sửa interface và mọi factory.

04Builder Xây từng bước

Vấn đềĐối tượng có nhiều tham số tùy chọn, constructor dài và dễ truyền nhầm thứ tự.
Ý tưởngTạo đối tượng qua chuỗi lời gọi có tên rõ ràng, cuối cùng gọi build().
class HttpRequest {
  constructor(
    readonly method: string, readonly url: string,
    readonly headers: Record<string, string>, readonly body?: string,
    readonly timeoutMs = 5000,
  ) {}
}

class RequestBuilder {
  private method = "GET";
  private headers: Record<string, string> = {};
  private body?: string;
  private timeoutMs = 5000;
  constructor(private url: string) {}

  post(body: unknown) { this.method = "POST"; this.body = JSON.stringify(body); return this; }
  header(k: string, v: string) { this.headers[k] = v; return this; }
  timeout(ms: number) { this.timeoutMs = ms; return this; }
  build() { return new HttpRequest(this.method, this.url, this.headers, this.body, this.timeoutMs); }
}

const req = new RequestBuilder("/orders")
  .post({ sku: "A1", qty: 2 })
  .header("Idempotency-Key", crypto.randomUUID())
  .timeout(3000)
  .build();
Khi nào dùngĐối tượng phức tạp, nhiều tùy chọn: query builder, HTTP request, dữ liệu test.
Lưu ýVới TypeScript, một object tham số { url, method?, timeout? } thường đã đủ; chỉ dùng Builder khi cần kiểm tra từng bước hoặc tạo theo nhiều giai đoạn.

05Prototype Nhân bản

Vấn đềTạo đối tượng mới từ đầu tốn kém hoặc phức tạp, trong khi đã có sẵn một mẫu gần giống.
Ý tưởngSao chép một đối tượng mẫu rồi chỉnh phần khác biệt.
interface Cloneable<T> { clone(): T; }

class ReportTemplate implements Cloneable<ReportTemplate> {
  constructor(public title: string, public sections: string[], public style: { font: string }) {}

  clone(): ReportTemplate {
    // Deep copy so the clone does not share nested objects
    return new ReportTemplate(this.title, [...this.sections], { ...this.style });
  }
}

const base = new ReportTemplate("Báo cáo tháng", ["Doanh thu", "Chi phí"], { font: "Inter" });
const q4 = base.clone();
q4.title = "Báo cáo quý 4";
q4.sections.push("Dự báo");

// structuredClone() also works for plain data objects
Khi nào dùngNhiều đối tượng chỉ khác nhau vài thuộc tính, cấu hình mặc định, dữ liệu test.
Lưu ýCẩn thận shallow copy: object lồng nhau bị dùng chung giữa bản gốc và bản sao.
