OOP: nền móng của mọi design pattern

Lập trình hướng đối tượng gom dữ liệu và hành vi xử lý dữ liệu đó vào cùng một đơn vị gọi là đối tượng. Design pattern chính là những cách kết hợp class, interface, kế thừa và đa hình đã được kiểm chứng, nên cần nắm chắc phần này trước.

01Class & Object

Class là bản thiết kế, object (instance) là thứ được tạo ra từ bản thiết kế đó bằng new. Mỗi object có dữ liệu riêng nhưng dùng chung các method của class.

class Product {
  // Properties (fields): data each object holds
  name: string;
  price: number;

  // Constructor runs once when "new" is called
  constructor(name: string, price: number) {
    this.name = name;   // "this" is the object being created
    this.price = price;
  }

  // Method: behaviour that works on this object's data
  priceWithVat(rate = 0.1) {
    return this.price * (1 + rate);
  }
}

const pho = new Product("Phở bò", 50_000);   // an object (instance)
const tra = new Product("Trà đá", 5_000);    // another, with its own data
pho.priceWithVat(); // 55000

// Shorthand: parameter properties declare and assign in one line
class Customer {
  constructor(public readonly id: string, private email: string) {}
}

03Đóng gói & access modifier

class BankAccount {
  readonly id: string;              // set once, never reassigned
  #balance = 0;                     // truly private at runtime (JS private field)
  protected history: number[] = []; // visible to subclasses
  private static fee = 1_000;       // private to the class

  constructor(id: string) { this.id = id; }

  // Getter: read-only view of internal state
  get balance() { return this.#balance; }

  // State changes only through methods that enforce rules
  deposit(amount: number) {
    if (amount <= 0) throw new Error("Amount must be positive");
    this.#balance += amount;
    this.history.push(amount);
  }

  withdraw(amount: number) {
    const total = amount + BankAccount.fee;
    if (total > this.#balance) throw new Error("Insufficient funds");
    this.#balance -= total;
    this.history.push(-total);
  }
}

const acc = new BankAccount("A-1");
acc.deposit(500_000);
acc.balance;          // 500000
// acc.balance = 0;   // error: no setter
// acc.#balance;      // error: private field

04Static: thuộc về class, không thuộc về object

Thành viên static gắn với chính class, chỉ có một bản dùng chung, gọi qua tên class (Order.count) mà không cần tạo object. Thành viên thường (instance) thì mỗi object có một bản riêng.

class Order {
  // Static property: one shared value for the whole class
  static count = 0;
  static readonly MAX_ITEMS = 50;

  // Static block: runs once when the class is defined
  static {
    Order.count = Number(process.env.ORDER_SEED ?? 0);
  }

  readonly id: number;
  items: string[] = [];

  constructor() {
    Order.count++;            // instance code can read/write static members
    this.id = Order.count;
  }

  // Static method: no "this" object; often used as a named factory
  static fromJson(json: string): Order {
    const data = JSON.parse(json);
    const o = new Order();
    o.items = data.items;
    return o;
  }

  // Static helper that does not need any instance data
  static isValidSku(sku: string) {
    return /^[A-Z]{3}-\d{3}$/.test(sku);
  }

  addItem(sku: string) {
    if (this.items.length >= Order.MAX_ITEMS) throw new Error("Too many items");
    if (!Order.isValidSku(sku)) throw new Error("Bad SKU");
    this.items.push(sku);
  }
}

const a = new Order();     // a.id = 1
const b = new Order();     // b.id = 2
Order.count;               // 2  (shared)
// a.count;                // error: count is not on the instance
Order.fromJson('{"items":["PHO-001"]}');

Khi nào dùng static

  • Hằng số của class: Order.MAX_ITEMS.
  • Factory method có tên: Order.fromJson(), Money.fromVnd(), rõ nghĩa hơn nhiều constructor.
  • Hàm tiện ích thuần không cần dữ liệu object: Order.isValidSku().
  • Đếm, cache, registry dùng chung: số object đã tạo, bảng tra cứu.
  • Singleton: static instance + static get() (xem tab Creational).
Cẩn thận với static có trạng thái: nó là biến toàn cục đội lốt class. Test chạy song song có thể dính dữ liệu của nhau, và không thay được bằng bản giả. Trong TypeScript, hàm tiện ích thuần thường nên là export function trong module thay vì class chỉ toàn static.

05Kế thừa

class Employee {
  constructor(public name: string, protected baseSalary: number) {}

  salary(): number { return this.baseSalary; }
  describe() { return `${this.name}: ${this.salary()} VND`; }
}

class Manager extends Employee {
  constructor(name: string, base: number, private teamSize: number) {
    super(name, base);               // must call parent constructor first
  }

  // "override" makes the intent explicit; compiler checks the parent has it
  override salary(): number {
    return super.salary() + this.teamSize * 2_000_000;   // reuse parent logic
  }
}

const m = new Manager("Lan", 20_000_000, 5);
m.describe();  // "Lan: 30000000 VND" — parent method calls the overridden salary()
  • Một class chỉ extends được một class cha, nhưng implements được nhiều interface.
  • Bật noImplicitOverride trong tsconfig để bắt buộc ghi override, tránh vô tình ghi đè.
  • Kế thừa thể hiện quan hệ “là một” (Manager là một Employee). Nếu chỉ là “có một” hay “dùng một” thì dùng composition.
Kế thừa sâu là nguồn rắc rối: sửa lớp cha làm vỡ lớp con ở xa (fragile base class). Ưu tiên composition, phần lớn pattern GoF được sinh ra để tránh kế thừa cứng nhắc.

06Abstract class & Interface

// Interface: a contract only, no implementation, no runtime code
interface Shippable {
  weightKg(): number;
}
interface Taxable {
  taxRate: number;
}

// Abstract class: partial implementation + abstract parts to fill in
abstract class Payment {
  constructor(protected amount: number) {}

  // Shared, concrete logic
  receipt() { return `${this.method()} - ${this.amount + this.fee()} VND`; }

  // Subclasses must implement these
  protected abstract fee(): number;
  abstract method(): string;
}

class CardPayment extends Payment {
  protected fee() { return Math.round(this.amount * 0.02); }
  method() { return "Thẻ"; }
}

// One class, one parent, many interfaces
class Parcel implements Shippable, Taxable {
  taxRate = 0.08;
  weightKg() { return 1.5; }
}

// new Payment(100);  // error: cannot instantiate an abstract class

07Đa hình & Generics

Đa hình qua interface và override

interface Shape { area(): number; name: string; }

class Circle implements Shape {
  name = "Tròn";
  constructor(private r: number) {}
  area() { return Math.PI * this.r ** 2; }
}
class Rect implements Shape {
  name = "Chữ nhật";
  constructor(private w: number, private h: number) {}
  area() { return this.w * this.h; }
}

// Same call, different behaviour per object
const shapes: Shape[] = [new Circle(1), new Rect(2, 3)];
shapes.forEach(s => console.log(s.name, s.area().toFixed(2)));

Overloading trong TypeScript

class Formatter {
  // Overload signatures (what callers see)
  format(value: number): string;
  format(value: Date): string;
  // Single implementation that handles all cases
  format(value: number | Date): string {
    return typeof value === "number"
      ? value.toLocaleString("vi-VN")
      : value.toLocaleDateString("vi-VN");
  }
}

JavaScript không cho viết nhiều method cùng tên, nên TypeScript chỉ có chữ ký overload kèm một phần thân duy nhất.

Generics: đa hình theo kiểu dữ liệu

class Repository<T extends { id: string }> {
  private items = new Map<string, T>();
  save(item: T) { this.items.set(item.id, item); }
  find(id: string): T | undefined { return this.items.get(id); }
}

const products = new Repository<{ id: string; name: string }>();
products.save({ id: "p1", name: "Phở" });
products.find("p1")?.name;  // typed as string

08Quan hệ giữa các lớp

Khi đọc sơ đồ của các design pattern, bạn sẽ gặp sáu loại quan hệ UML dưới đây. Xếp từ lỏng đến chặt.

Quan hệNghĩaTrong code
Dependency“Dùng tạm”Nhận làm tham số hoặc tạo trong một method, không giữ lại
Association“Biết đến”Giữ tham chiếu lâu dài: order.customer
Aggregation“Có”, phần sống độc lậpTeam giữ danh sách Employee; xóa Team, Employee vẫn còn
Composition“Gồm”, phần sống chết theo tổng thểOrder tự tạo OrderLine; xóa Order thì OrderLine mất theo

Realization“Hiện thực hợp đồng”class Parcel implements Shippable
 
class OrderLine { constructor(readonly sku: string, readonly qty: number) {} }

class Order {
  private lines: OrderLine[] = [];                 // composition: Order owns and creates its lines
  constructor(readonly customer: Customer) {}      // association: keeps a reference
  addLine(sku: string, qty: number) { this.lines.push(new OrderLine(sku, qty)); }
  print(printer: Printer) { printer.print(this); } // dependency: used only during the call
}

09Điểm riêng của TypeScript

  • Structural typing: TypeScript so sánh theo hình dạng, không theo tên. Object nào có đủ area() và name đều là Shape, không cần ghi implements. Ghi implements vẫn nên làm để compiler kiểm tra sớm.
  • Class vừa là giá trị vừa là kiểu: Product dùng được với new và cũng dùng làm kiểu let p: Product.
  • Interface không tồn tại lúc chạy: không dùng được x instanceof Shape; muốn kiểm tra thì viết type guard (x): x is Shape => "area" in x.
  • Mất this: truyền obj.method làm callback thì this bị mất. Dùng arrow function làm field (handle = () => …) hoặc .bind(this).
  • Dưới lớp vỏ là prototype: method nằm trên Product.prototype, mọi object dùng chung; field nằm trên từng object.
  • Không phải mọi thứ đều cần class. Hàm thuần và object literal thường gọn hơn cho logic không có trạng thái.
class Button {
  clicks = 0;
  onClickBroken() { this.clicks++; }       // "this" is lost when passed as a callback
  onClick = () => { this.clicks++; };      // arrow field keeps "this"
}
const btn = new Button();
setTimeout(btn.onClick, 0);                // works
// setTimeout(btn.onClickBroken, 0);       // TypeError: cannot read 'clicks' of undefined
