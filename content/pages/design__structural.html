Structural: cách ghép đối tượng

Bảy pattern về cách bọc, nối và tổ chức các đối tượng thành cấu trúc lớn hơn mà vẫn linh hoạt.

PatternTên ViệtÝ tưởng một câu
AdapterBộ chuyển đổiBọc đối tượng cũ trong một lớp hiện thực interface mới, chuyển đổi lời gọi qua lại.
BridgeCầu nốiTách thành hai hệ thống phân cấp, một bên giữ tham chiếu tới bên kia.
CompositeCây đối tượngLá và nhánh cùng hiện thực một interface; nhánh gọi đệ quy xuống các con.
DecoratorBọc thêm chức năngBọc đối tượng trong một lớp cùng interface, làm thêm việc trước hoặc sau khi gọi vào đối tượng bên trong. Có thể bọc nhiều lớp chồng nhau.
FacadeMặt tiềnTạo một lớp với vài phương thức đơn giản, bên trong điều phối các subsystem.
FlyweightDùng chung phần giống nhauTách phần dữ liệu không đổi (intrinsic) ra dùng chung; mỗi đối tượng chỉ giữ phần riêng (extrinsic).
ProxyĐại diệnMột đối tượng cùng interface đứng trước đối tượng thật và quyết định có chuyển lời gọi vào hay không.

01Adapter Bộ chuyển đổi

Vấn đềCó một thư viện hoặc API bên ngoài với interface khác với interface mà code của bạn đang dùng.
Ý tưởngBọc đối tượng cũ trong một lớp hiện thực interface mới, chuyển đổi lời gọi qua lại.
// Interface our app expects
interface PaymentGateway { charge(orderId: string, amountVnd: number): Promise<string>; }

// Third-party SDK with a different shape
class LegacyPayClient {
  makePayment(p: { ref: string; cents: number; currency: string }) {
    return Promise.resolve({ transactionId: "tx_" + p.ref });
  }
}

class LegacyPayAdapter implements PaymentGateway {
  constructor(private client: LegacyPayClient) {}

  async charge(orderId: string, amountVnd: number) {
    const res = await this.client.makePayment({ ref: orderId, cents: amountVnd * 100, currency: "VND" });
    return res.transactionId;
  }
}
Khi nào dùngTích hợp thư viện bên thứ ba, hệ thống cũ, đổi nhà cung cấp mà không sửa code nghiệp vụ.
Lưu ýChỉ chuyển đổi, không nhét logic nghiệp vụ vào adapter.

02Bridge Cầu nối

Vấn đềHai chiều thay đổi độc lập (loại thông báo × kênh gửi) khiến số lớp con nhân lên theo cấp số nhân.
Ý tưởngTách thành hai hệ thống phân cấp, một bên giữ tham chiếu tới bên kia.
// Implementation side: how to deliver
interface Channel { deliver(to: string, text: string): void; }
class EmailChannel implements Channel { deliver(to: string, t: string) { console.log("email", to, t); } }
class SmsChannel implements Channel { deliver(to: string, t: string) { console.log("sms", to, t); } }

// Abstraction side: what to say
abstract class Message {
  constructor(protected channel: Channel) {}
  abstract send(to: string): void;
}
class OrderShipped extends Message {
  constructor(channel: Channel, private orderId: string) { super(channel); }
  send(to: string) { this.channel.deliver(to, `Đơn ${this.orderId} đã giao`); }
}

new OrderShipped(new SmsChannel(), "42").send("0901...");
// N messages + M channels classes, instead of N x M subclasses like SmsOrderShipped
Khi nào dùngHai khía cạnh cùng phát triển: nền tảng × giao diện, loại báo cáo × định dạng xuất.
Lưu ýHay bị nhầm với Adapter. Bridge thiết kế từ đầu để tách; Adapter vá cho hai thứ có sẵn khớp nhau.

03Composite Cây đối tượng

Vấn đềDữ liệu dạng cây (thư mục và file, menu và mục con, đơn hàng và combo) mà muốn xử lý nút lá và nút nhánh như nhau.
Ý tưởngLá và nhánh cùng hiện thực một interface; nhánh gọi đệ quy xuống các con.
interface CartItem { price(): number; }

class Product implements CartItem {
  constructor(private name: string, private unitPrice: number) {}
  price() { return this.unitPrice; }
}

class Combo implements CartItem {
  private items: CartItem[] = [];
  constructor(private discount = 0) {}
  add(item: CartItem) { this.items.push(item); return this; }
  price() {
    // Treat children uniformly, whether products or nested combos
    const sum = this.items.reduce((s, i) => s + i.price(), 0);
    return sum * (1 - this.discount);
  }
}

const lunch = new Combo(0.1).add(new Product("Phở", 50000)).add(new Product("Trà đá", 5000));
const cart = new Combo().add(lunch).add(new Product("Bánh flan", 15000));
console.log(cart.price()); // 64500
Khi nào dùngCấu trúc cây: UI component, cây thư mục, tổ chức phòng ban, biểu thức.
Lưu ýInterface chung có thể buộc lá hiện thực các phương thức chỉ nhánh mới cần (như add).

04Decorator Bọc thêm chức năng

Vấn đềMuốn thêm log, cache, retry cho một service mà không sửa code gốc và không tạo lớp con cho từng tổ hợp.
Ý tưởngBọc đối tượng trong một lớp cùng interface, làm thêm việc trước hoặc sau khi gọi vào đối tượng bên trong. Có thể bọc nhiều lớp chồng nhau.
interface UserRepo { findById(id: string): Promise<User | null>; }

class DbUserRepo implements UserRepo {
  async findById(id: string) { return db.users.find(id); }
}

class CachedUserRepo implements UserRepo {
  private cache = new Map<string, User | null>();
  constructor(private inner: UserRepo) {}
  async findById(id: string) {
    if (!this.cache.has(id)) this.cache.set(id, await this.inner.findById(id));
    return this.cache.get(id)!;
  }
}

class LoggedUserRepo implements UserRepo {
  constructor(private inner: UserRepo) {}
  async findById(id: string) {
    const t = Date.now();
    try { return await this.inner.findById(id); }
    finally { console.log(`findById ${id} took ${Date.now() - t}ms`); }
  }
}

// Compose behaviours freely
const repo: UserRepo = new LoggedUserRepo(new CachedUserRepo(new DbUserRepo()));
Khi nào dùngMiddleware, cache, retry, logging, kiểm tra quyền quanh một service. Middleware của Express hay interceptor của gRPC là cùng ý tưởng.
Lưu ýThứ tự bọc quan trọng: log ngoài cache khác log trong cache. Đừng nhầm với cú pháp @decorator của TypeScript, dù có thể dùng nó để hiện thực.

05Facade Mặt tiền

Vấn đềMột nghiệp vụ cần gọi nhiều subsystem theo đúng thứ tự; mọi nơi gọi đều phải biết chi tiết đó.
Ý tưởngTạo một lớp với vài phương thức đơn giản, bên trong điều phối các subsystem.
class CheckoutFacade {
  constructor(
    private inventory: InventoryService,
    private payment: PaymentService,
    private shipping: ShippingService,
    private notifier: Notifier,
  ) {}

  // One simple call hides four subsystems
  async checkout(cart: Cart, user: User) {
    await this.inventory.reserve(cart.items);
    const txId = await this.payment.charge(user.id, cart.total);
    const tracking = await this.shipping.schedule(cart, user.address);
    await this.notifier.send(user.email, `Đã đặt hàng, mã vận đơn ${tracking}`);
    return { txId, tracking };
  }
}
Khi nào dùngĐơn giản hóa thư viện phức tạp, gom một use case thành một điểm gọi, tầng service trong kiến trúc nhiều lớp.
Lưu ýFacade dễ phình thành “god object” làm mọi thứ. Giữ nó mỏng, chỉ điều phối.

06Flyweight Dùng chung phần giống nhau

Vấn đềHàng trăm nghìn đối tượng nhỏ cùng chứa một phần dữ liệu lặp lại, tốn bộ nhớ.
Ý tưởngTách phần dữ liệu không đổi (intrinsic) ra dùng chung; mỗi đối tượng chỉ giữ phần riêng (extrinsic).
// Shared, immutable part
class TreeType {
  constructor(readonly name: string, readonly texture: Uint8Array) {}
}

class TreeTypeFactory {
  private static cache = new Map<string, TreeType>();
  static get(name: string): TreeType {
    let t = this.cache.get(name);
    if (!t) { t = new TreeType(name, loadTexture(name)); this.cache.set(name, t); }
    return t;
  }
}

// Unique part per object: only coordinates and a reference
class Tree {
  constructor(readonly x: number, readonly y: number, readonly type: TreeType) {}
}

const forest = Array.from({ length: 100_000 }, (_, i) =>
  new Tree(i % 500, Math.floor(i / 500), TreeTypeFactory.get(i % 2 ? "oak" : "pine")));
// 100k trees share only 2 textures
Khi nào dùngGame, trình soạn thảo văn bản (định dạng ký tự), bản đồ, cache chuỗi lặp lại.
Lưu ýChỉ đáng làm khi đo thấy vấn đề bộ nhớ thật; code phức tạp hơn đáng kể.

07Proxy Đại diện

Vấn đềCần kiểm soát truy cập tới một đối tượng: tải trễ, kiểm tra quyền, gọi từ xa, giới hạn tần suất.
Ý tưởngMột đối tượng cùng interface đứng trước đối tượng thật và quyết định có chuyển lời gọi vào hay không.
interface Document { read(): string; }

class RealDocument implements Document {
  private content: string;
  constructor(path: string) { this.content = loadHugeFile(path); } // expensive
  read() { return this.content; }
}

class SecureLazyDocument implements Document {
  private real?: RealDocument;
  constructor(private path: string, private user: User) {}

  read() {
    if (!this.user.roles.includes("viewer")) throw new Error("Forbidden");
    this.real ??= new RealDocument(this.path); // load only when first needed
    return this.real.read();
  }
}

// JavaScript also has a built-in Proxy object for intercepting property access
Khi nào dùngLazy loading, phân quyền, stub gọi từ xa (gRPC client stub chính là proxy), rate limit.
Lưu ýKhác Decorator ở ý định: Proxy kiểm soát truy cập và thường tự quản lý đối tượng thật; Decorator thêm hành vi và nhận đối tượng từ bên ngoài.
