Behavioral: cách đối tượng phối hợp

Mười một pattern về chia trách nhiệm và giao tiếp giữa các đối tượng: ai làm gì, ai báo cho ai.

PatternTên ViệtÝ tưởng một câu
Chain of ResponsibilityChuỗi xử lýXếp các handler thành chuỗi; mỗi handler xử lý rồi quyết định chuyển tiếp hay dừng.
CommandĐóng gói yêu cầuBiến mỗi thao tác thành một đối tượng chứa đủ thông tin để thực hiện và hoàn tác.

ObserverNgười quan sátĐối tượng giữ danh sách subscriber và thông báo cho tất cả khi có sự kiện.

01Chain of Responsibility Chuỗi xử lý

Vấn đềMột request cần qua nhiều bước kiểm tra (xác thực, phân quyền, validate), bước nào cũng có thể dừng lại.
Ý tưởngXếp các handler thành chuỗi; mỗi handler xử lý rồi quyết định chuyển tiếp hay dừng.
type Ctx = { user?: User; body: unknown; };
type Handler = (ctx: Ctx, next: () => Promise<void>) => Promise<void>;

const authenticate: Handler = async (ctx, next) => {
  ctx.user = await verifyToken();
  if (!ctx.user) throw new HttpError(401);
  await next();
};
const authorize: Handler = async (ctx, next) => {
  if (!ctx.user!.roles.includes("admin")) throw new HttpError(403);
  await next();
};
const validate: Handler = async (ctx, next) => {
  if (!isValidOrder(ctx.body)) throw new HttpError(422);
  await next();
};

function chain(handlers: Handler[], final: (ctx: Ctx) => Promise<void>) {
  return (ctx: Ctx) => {
    const run = (i: number): Promise<void> =>
      i < handlers.length ? handlers[i](ctx, () => run(i + 1)) : final(ctx);
    return run(0);
  };
}

const createOrder = chain([authenticate, authorize, validate], async ctx => { /* save */ });
Khi nào dùngMiddleware HTTP (Express, Koa), pipeline xử lý sự kiện, duyệt đơn nhiều cấp.
Lưu ýChuỗi dài khó debug; request có thể đi hết chuỗi mà không ai xử lý.

02Command Đóng gói yêu cầu

Vấn đềMuốn xếp hàng, ghi log, hoàn tác (undo) hoặc thực hiện lại các thao tác.
Ý tưởngBiến mỗi thao tác thành một đối tượng chứa đủ thông tin để thực hiện và hoàn tác.
interface Command { execute(): void; undo(): void; }

class AddItem implements Command {
  constructor(private cart: string[], private item: string) {}
  execute() { this.cart.push(this.item); }
  undo() { this.cart.splice(this.cart.lastIndexOf(this.item), 1); }
}

class History {
  private done: Command[] = [];
  run(cmd: Command) { cmd.execute(); this.done.push(cmd); }
  undo() { this.done.pop()?.undo(); }
}

const cart: string[] = [];
const h = new History();
h.run(new AddItem(cart, "Phở"));
h.run(new AddItem(cart, "Trà"));
h.undo();            // cart = ["Phở"]
Khi nào dùngUndo/redo, hàng đợi tác vụ, macro, ghi lại thao tác. Message trong RabbitMQ chứa lệnh cũng là Command được tuần tự hóa.
Lưu ýMỗi thao tác một lớp nên số lớp tăng nhanh; với thao tác đơn giản, một hàm là đủ.

03Iterator Duyệt tuần tự

Vấn đềMuốn duyệt qua một tập hợp (cây, danh sách phân trang từ API) mà không lộ cấu trúc bên trong.
Ý tưởngCung cấp một cách lấy phần tử tiếp theo theo chuẩn chung. JavaScript có sẵn giao thức iterator và generator.
// Async generator: walk every page of a cursor-paginated REST API
async function* allOrders(api: Api) {
  let cursor: string | undefined;
  do {
    const page = await api.get("/orders", { after: cursor, size: 100 });
    yield* page.items;          // hand out items one by one
    cursor = page.nextCursor;
  } while (cursor);
}

for await (const order of allOrders(api)) {
  if (order.total > 1_000_000) console.log(order.id);
}
Khi nào dùngDuyệt dữ liệu phân trang, đọc file lớn theo dòng, duyệt cây.
Lưu ýĐã có sẵn trong ngôn ngữ; hiếm khi phải tự viết lớp Iterator riêng.

04Mediator Trung gian điều phối

Vấn đềNhiều thành phần gọi qua lại lẫn nhau tạo thành mạng phụ thuộc rối.
Ý tưởngCác thành phần chỉ nói chuyện với một mediator; mediator quyết định ai cần phản ứng.
type Event = "countryChanged" | "submitClicked";

class CheckoutForm {
  constructor(
    private country: Select, private city: Select,
    private shippingFee: Label, private submit: Button,
  ) {}

  // Components report to the mediator instead of calling each other
  notify(event: Event) {
    if (event === "countryChanged") {
      this.city.setOptions(citiesOf(this.country.value));
      this.shippingFee.setText(feeFor(this.country.value));
    }
    if (event === "submitClicked") {
      this.submit.disable();
    }
  }
}
Khi nào dùngForm có các trường phụ thuộc nhau, chat room, điều phối workflow. Orchestrator trong Saga là mediator ở cấp hệ thống.
Lưu ýMediator có thể ôm hết logic và trở nên khổng lồ.

05Memento Lưu trạng thái

Vấn đềCần lưu và khôi phục trạng thái của đối tượng mà không để bên ngoài sửa trực tiếp nội tạng của nó.
Ý tưởngĐối tượng tự xuất một bản chụp trạng thái (chỉ đọc) và tự khôi phục từ bản chụp đó.
class Editor {
  private text = "";
  private cursor = 0;

  type(s: string) { this.text += s; this.cursor = this.text.length; }

  save() {
    // Snapshot is immutable and opaque to callers
    return Object.freeze({ text: this.text, cursor: this.cursor });
  }
  restore(m: ReturnType<Editor["save"]>) { this.text = m.text; this.cursor = m.cursor; }
}

const ed = new Editor();
const snapshots = [];
ed.type("Xin ");
snapshots.push(ed.save());
ed.type("chàoo");          // typo we want to undo
ed.restore(snapshots.pop()!);
Khi nào dùngUndo, lưu nháp, checkpoint trong game, rollback cấu hình.
Lưu ýBản chụp lớn và nhiều thì tốn bộ nhớ; cân nhắc lưu chênh lệch hoặc giới hạn số bản.

06Observer Người quan sát

Vấn đềKhi một đối tượng thay đổi, nhiều nơi khác cần biết, nhưng không muốn đối tượng đó phải biết từng nơi.
Ý tưởngĐối tượng giữ danh sách subscriber và thông báo cho tất cả khi có sự kiện.
type Listener<T> = (data: T) => void;

class EventBus<Events extends Record<string, unknown>> {
  private listeners: { [K in keyof Events]?: Listener<Events[K]>[] } = {};

  on<K extends keyof Events>(event: K, fn: Listener<Events[K]>) {
    (this.listeners[event] ??= []).push(fn);
    return () => { this.listeners[event] = this.listeners[event]!.filter(f => f !== fn); };
  }
  emit<K extends keyof Events>(event: K, data: Events[K]) {
    this.listeners[event]?.forEach(fn => fn(data));
  }
}

const bus = new EventBus<{ orderPaid: { id: string; total: number } }>();
bus.on("orderPaid", e => sendReceipt(e.id));
bus.on("orderPaid", e => updateRevenue(e.total));
bus.emit("orderPaid", { id: "42", total: 350000 });
Khi nào dùngSự kiện UI, reactive state, domain event trong một service. Kafka, RabbitMQ fanout, NATS là Observer phân tán qua mạng.
Lưu ýKhó lần theo luồng chạy; nhớ hủy đăng ký để tránh rò rỉ bộ nhớ.

07State Trạng thái

Vấn đềHành vi thay đổi theo trạng thái, code đầy if (status === …) lặp lại ở mọi phương thức.
Ý tưởngMỗi trạng thái là một đối tượng tự quyết định hành vi và trạng thái kế tiếp.
type OrderStatus = "pending" | "paid" | "shipped" | "cancelled";

// Allowed transitions in one place
const transitions: Record<OrderStatus, Partial<Record<string, OrderStatus>>> = {
  pending:   { pay: "paid", cancel: "cancelled" },
  paid:      { ship: "shipped", cancel: "cancelled" },
  shipped:   {},
  cancelled: {},
};

class Order {
  constructor(public status: OrderStatus = "pending") {}
  apply(action: "pay" | "ship" | "cancel") {
    const next = transitions[this.status][action];
    if (!next) throw new Error(`Không thể ${action} khi đơn đang ${this.status}`);
    this.status = next;
  }
}

const o = new Order();
o.apply("pay");
o.apply("ship");
o.apply("cancel"); // throws
Khi nào dùngVòng đời đơn hàng, thanh toán, kết nối mạng, quy trình duyệt. Circuit Breaker cũng là một state machine.
Lưu ýÍt trạng thái và hành vi đơn giản thì một bảng chuyển trạng thái như trên gọn hơn nhiều lớp State.

08Strategy Chiến lược

Vấn đềMột việc có nhiều thuật toán thay thế (tính phí ship, giảm giá, sắp xếp) và phải chọn lúc chạy.
Ý tưởngMỗi thuật toán là một đối tượng hoặc hàm cùng interface; nơi dùng nhận vào và gọi.
type ShippingStrategy = (weightKg: number, distanceKm: number) => number;

const standard: ShippingStrategy = (w, d) => 15000 + w * 3000 + d * 500;
const express: ShippingStrategy  = (w, d) => 30000 + w * 5000 + d * 800;
const freeOver500k = (total: number, base: ShippingStrategy): ShippingStrategy =>
  (w, d) => (total >= 500_000 ? 0 : base(w, d));

class ShippingCalculator {
  constructor(private strategy: ShippingStrategy) {}
  setStrategy(s: ShippingStrategy) { this.strategy = s; }
  fee(w: number, d: number) { return this.strategy(w, d); }
}

const calc = new ShippingCalculator(standard);
calc.setStrategy(freeOver500k(620_000, express));
calc.fee(2, 10); // 0
Khi nào dùngThuật toán thay được: giá, xác thực, nén, sắp xếp, retry policy.
Lưu ýTrong TypeScript, strategy thường chỉ là một hàm; không cần cả cây lớp.

09Template Method Khuôn mẫu

Vấn đềNhiều quy trình có cùng khung các bước, chỉ khác nhau vài bước.
Ý tưởngLớp cha định nghĩa trình tự cố định; lớp con hiện thực các bước riêng.
abstract class DataImporter<Row> {
  // The fixed algorithm skeleton
  async run(file: string) {
    const raw = await this.read(file);
    const rows = this.parse(raw);
    const valid = rows.filter(r => this.validate(r));
    await this.save(valid);
    console.log(`Imported ${valid.length}/${rows.length}`);
  }
  protected read(file: string) { return fs.promises.readFile(file, "utf8"); }
  protected abstract parse(raw: string): Row[];
  protected abstract validate(row: Row): boolean;
  protected abstract save(rows: Row[]): Promise<void>;
}

class CsvProductImporter extends DataImporter<Product> {
  protected parse(raw: string) { return raw.split("\n").map(toProduct); }
  protected validate(p: Product) { return p.price > 0; }
  protected save(ps: Product[]) { return db.products.insertMany(ps); }
}
Khi nào dùngImport/export dữ liệu, xử lý request có khung chung, test fixture.
Lưu ýDựa vào kế thừa nên cứng; nhiều khi truyền các bước vào dưới dạng hàm (Strategy) linh hoạt hơn.

10Visitor Khách thăm

Vấn đềCần thêm nhiều thao tác mới (xuất JSON, tính giá, kiểm tra) lên một cấu trúc đối tượng ổn định mà không sửa từng lớp.
Ý tưởngĐưa mỗi thao tác vào một visitor có hàm riêng cho từng loại phần tử. Trong TypeScript, discriminated union kèm switch đạt cùng mục tiêu gọn hơn.
type Node =
  | { kind: "num"; value: number }
  | { kind: "add"; left: Node; right: Node }
  | { kind: "mul"; left: Node; right: Node };

// Each "visitor" is just a function that handles every node kind
const evaluate = (n: Node): number => {
  switch (n.kind) {
    case "num": return n.value;
    case "add": return evaluate(n.left) + evaluate(n.right);
    case "mul": return evaluate(n.left) * evaluate(n.right);
  }
};

const print = (n: Node): string => {
  switch (n.kind) {
    case "num": return String(n.value);
    case "add": return `(${print(n.left)} + ${print(n.right)})`;
    case "mul": return `${print(n.left)} * ${print(n.right)}`;
  }
};

const expr: Node = { kind: "mul", left: { kind: "num", value: 2 },
  right: { kind: "add", left: { kind: "num", value: 3 }, right: { kind: "num", value: 4 } } };
print(expr);    // 2 * (3 + 4)
evaluate(expr); // 14
Khi nào dùngAST của compiler/linter, xuất một cấu trúc ra nhiều định dạng.
Lưu ýThêm loại phần tử mới thì phải sửa mọi visitor. Với TypeScript, bật kiểm tra exhaustive để compiler nhắc.

11Interpreter Thông dịch

Vấn đềCó một ngôn ngữ nhỏ (luật giảm giá, bộ lọc tìm kiếm) cần đọc và chạy.
Ý tưởngBiểu diễn mỗi quy tắc ngữ pháp bằng một đối tượng có hàm interpret, ghép lại thành cây.
type Ctx = { total: number; tier: string };
interface Rule { test(ctx: Ctx): boolean; }

const totalOver = (n: number): Rule => ({ test: c => c.total > n });
const tierIs = (t: string): Rule => ({ test: c => c.tier === t });
const and = (...rs: Rule[]): Rule => ({ test: c => rs.every(r => r.test(c)) });
const or = (...rs: Rule[]): Rule => ({ test: c => rs.some(r => r.test(c)) });

// "total > 500k AND (tier = gold OR tier = vip)"
const vipDiscount = and(totalOver(500_000), or(tierIs("gold"), tierIs("vip")));
vipDiscount.test({ total: 600_000, tier: "gold" }); // true
Khi nào dùngLuật nghiệp vụ cấu hình được, bộ lọc truy vấn, biểu thức tính toán.
Lưu ýNgôn ngữ lớn thì dùng parser generator; pattern này hợp với ngữ pháp nhỏ.
