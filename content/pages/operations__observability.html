Observability: logs, metrics, traces

Log chỉ là một phần. Để hiểu hệ thống nhiều service đang chạy thế nào, cần ba loại tín hiệu bổ sung cho nhau, nối với nhau bằng trace ID.

Cách dùng thường gặp: metric báo động (tỉ lệ lỗi tăng) → trace chỉ ra service chậm hoặc lỗi → log của đúng request đó cho biết nguyên nhân.

02Distributed tracing

Một trace là toàn bộ hành trình của một request; mỗi đoạn công việc (gọi API, query DB, publish message) là một span có thời điểm bắt đầu, thời lượng và span cha. Trace ID được truyền giữa các service qua header chuẩn W3C traceparent.

traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01
             │  └ trace id (32 hex)               └ parent span id   └ sampled

03OpenTelemetry

OpenTelemetry (OTel) là chuẩn mở, thuộc CNCF, để thu thập cả traces, metrics và logs, rồi gửi tới bất kỳ backend nào. Viết một lần, đổi nhà cung cấp không cần sửa code.

// tracing.ts — load before anything else: node --import ./tracing.js main.js
import { NodeSDK } from "@opentelemetry/sdk-node";
import { getNodeAutoInstrumentations } from "@opentelemetry/auto-instrumentations-node";
import { OTLPTraceExporter } from "@opentelemetry/exporter-trace-otlp-http";

new NodeSDK({
  serviceName: "order-svc",
  traceExporter: new OTLPTraceExporter({ url: "http://otel-collector:4318/v1/traces" }),
  // Auto-instruments http, express, pg, ioredis, kafkajs, grpc ... and injects traceparent
  instrumentations: [getNodeAutoInstrumentations()],
}).start();
import { trace } from "@opentelemetry/api";

const tracer = trace.getTracer("checkout");

export async function placeOrder(input: PlaceOrderInput) {
  // A manual span for business logic you want to see in the waterfall
  return tracer.startActiveSpan("placeOrder", async span => {
    span.setAttribute("order.items", input.items.length);
    try {
      return await doPlaceOrder(input);
    } catch (err) {
      span.recordException(err as Error);
      throw err;
    } finally {
      span.end();
    }
  });
}

// Put trace ids into every log line so logs and traces link together
const logger = pino({
  mixin() {
    const ctx = trace.getActiveSpan()?.spanContext();
    return ctx ? { traceId: ctx.traceId, spanId: ctx.spanId } : {};
  },
});

Dùng phân vị (p95, p99) cho độ trễ, không dùng trung bình: trung bình 100 ms có thể che giấu 1% người dùng phải chờ 5 giây.

05Cảnh báo

  • Cảnh báo theo triệu chứng người dùng thấy (tỉ lệ lỗi, độ trễ) thay vì nguyên nhân (CPU 80%).
  • Mỗi cảnh báo phải có hành động rõ ràng; cảnh báo không ai xử lý sẽ khiến mọi người bỏ qua cả cảnh báo thật.
  • Đặt mục tiêu SLO (ví dụ 99.9% request thành công dưới 300 ms trong 30 ngày) và cảnh báo khi tiêu hao error budget quá nhanh.
  • Kèm link tới dashboard và runbook ngay trong cảnh báo.
